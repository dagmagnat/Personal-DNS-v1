# Personal DNS — свой DNS без сложной установки

Отдельный проект, не обновление Nexus. Русский установщик создаёт личный
DNS на **AdGuard Home** с DoH и DoT. Можно поставить рядом с Nexus/3x-ui:
установщик не останавливает Caddy, не забирает порт 80, не правит firewall
и системный DNS сервера.

**Статус первой версии:** локальные unit-тесты и проверка синтаксиса выполнены.
Полная установка на Linux/VPS и выдача реального сертификата ещё не проверены.
В GitHub Actions добавлен Docker-тест. Перед рабочим использованием дождитесь
его зелёного результата и выполните `sudo dnsctl doctor` на своём VPS.

## 1. Что подготовить

- VPS с Ubuntu 22.04/24.04 или Debian 12/13, systemd, root/sudo и публичным IPv4.
  Ориентир: 1 CPU, 1 ГБ RAM, 5 ГБ свободного диска. Это ориентир, не гарантия
  для большой нагрузки. При совместной установке учитывайте и другие панели.
- Домен, например `example.com`, и поддомен `dns.example.com`.
- **Простой автоматический вариант:** DNS-зона домена находится в Cloudflare.
  Регистратор домена может быть любым. Платный тариф Cloudflare не требуется
  для самого DNS-01; условия и доступность провайдера проверяйте отдельно.
- В Cloudflare создайте **API Token**: `Zone → DNS → Edit`, ограниченный только
  нужной зоной. Не используйте Global API Key. Установщик попросит токен
  скрытым вводом; он хранится только на VPS, не в репозитории.
- Если Cloudflare не используете: подготовьте доверенный сертификат,
  покрывающий **`dns.example.com` и `*.dns.example.com`**, плюс приватный ключ.
  Автоматическое продление в этом режиме — обязанность вашего ACME-клиента.

Без домена эта версия не предназначена для Android Private DNS. Это DNS для
клиентских запросов, а не авторитетные NS-серверы для обслуживания доменных зон.

## 2. Загрузить проект в GitHub

Создайте репозиторий, например `Personal-DNS`, и загрузите **содержимое** этой
папки в корень, включая `.github`, `.gitignore` и `.gitattributes`.
На верхнем уровне должны находиться `install.sh`, `dnsctl.py` и `README.md`.
**Никакие файлы с VPS — state.json, .env, PEM, backups, cloudflare.ini — туда
загружать нельзя.**

## 3. Установить

В SSH сервера выполните (замените `YOUR_LOGIN` на свой GitHub-логин):

```bash
sudo -i
apt-get update
apt-get install -y git
git clone https://github.com/YOUR_LOGIN/Personal-DNS.git
cd Personal-DNS
bash install.sh
```

Либо скопируйте распакованную папку проекта на VPS и запустите из неё
`sudo bash install.sh`. Скрипт не рассчитан на `curl ... | bash`, поскольку
ему нужен соседний `dnsctl.py`.

Ответьте на вопросы:

1. Поддомен DNS — `dns.example.com`, без `https://`.
2. Публичный IPv4 именно этого VPS.
3. Сертификат: **Enter = Cloudflare**, либо `2` для готового сертификата.
4. Для Cloudflare — email и API Token. Для своего — пути fullchain/privkey.
5. Блокировка рекламы: Enter = выключена, `да` = включена.
6. Проверьте итог и подтвердите `ДА`.

Пароль админки и личный идентификатор генерируются автоматически. Установка
использует AdGuard Home **v0.107.79**, актуальный стабильный релиз на момент
подготовки. Образы закрепляются по digest после загрузки; неожиданных
автоматических обновлений DNS-приложения нет.

## 4. Создать две DNS-записи

В Cloudflare → DNS добавьте (пример для зоны `example.com`):

| Type | Name | Content | Proxy |
|---|---|---|---|
| A | `dns` | IPv4 VPS | **DNS only**, серая тучка |
| A | `*.dns` | тот же IPv4 | **DNS only**, серая тучка |

У другого DNS-провайдера создаются аналогичные записи. Не добавляйте AAAA:
эта версия публикует входящие службы только по IPv4. Удалять чужие записи
не нужно — используйте свободный поддомен.

Сертификат получается через TXT/DNS-01 и не требует освобождать 80/443.
Установщик **не создаёт эти A-записи за вас**. Дождитесь их распространения.

Откройте в firewall провайдера входящие **TCP 853** и выбранный установщиком
HTTPS-порт. SSH оставьте доступным. Ничего не открывайте для UDP 53 или админки.
Если используете UFW, разрешите только нужные порты; Docker может обходить
часть правил UFW, поэтому основной контроль публикации задан самим Compose.

Проверьте:

```bash
sudo dnsctl doctor
sudo dnsctl info
```

`doctor` делает настоящий DNS-запрос через DoH и DoT, проверяет TLS и запрет
неизвестного клиента. Проверка с самого VPS не заменяет проверку с телефона:
внешний firewall может блокировать входящие соединения.

## 5. Подключить телефон или приложение

`dnsctl info` покажет **ваши готовые адреса**, например:

- Android → Настройки → Частный DNS → Имя провайдера:
  `СЛУЧАЙНЫЙ_ID.dns.example.com` — **без `https://` и без порта**.
- DoH в браузере/VPN-приложении:
  `https://dns.example.com/dns-query/СЛУЧАЙНЫЙ_ID`.
- Если 443 занят Nexus: `https://dns.example.com:8443/dns-query/СЛУЧАЙНЫЙ_ID`
  (или 9443 — используйте именно напечатанный адрес).
- DoT в совместимом приложении: `tls://СЛУЧАЙНЫЙ_ID.dns.example.com`.

Один адрес DoH нельзя вставлять в поле обычного DNS, принимающее только IP.
Обычный DNS на 53 этой версией намеренно не публикуется. Для старого роутера
нужен локальный DoH/DoT-клиент или отдельная VPN-схема.
DNS не заменяет VPN и не гарантирует доступ к заблокированным сайтам.

## 6. Открыть админку

На VPS выполните `sudo dnsctl info`. Скопируйте строку `ssh -L ...` и выполните
её **на своём компьютере** в PowerShell/терминале. Не закрывайте SSH.
Откройте `http://127.0.0.1:18080`, логин **admin**, пароль из вывода.
На телефоне нужен SSH-клиент с поддержкой local port forwarding.

Порт админки не опубликован на VPS вообще. Туннель ведёт к внутреннему IP
контейнера; если контейнер пересоздан и IP изменился, снова выполните
`dnsctl info`. Если ваш SSH-пользователь не root или порт SSH нестандартный,
скорректируйте напечатанную команду (`-p ПОРТ`, ваш пользователь).

Пароль можно менять в AdGuard Home. `dnsctl info` хранит **первоначальный**
пароль и не умеет восстановить новый из хеша. Не меняйте `allowed_clients`,
порты, TLS и пути сертификатов без понимания последствий: это защитная
конфигурация установщика. Фильтры рекламы можно менять через интерфейс.

## Команды

| Команда | Назначение |
|---|---|
| `sudo dnsctl` | Короткое меню |
| `sudo dnsctl info` | Адреса, туннель и первоначальные данные входа |
| `sudo dnsctl status` | Состояние контейнеров |
| `sudo dnsctl doctor` | Проверить DNS и ограничения |
| `sudo dnsctl logs` | Последние сообщения; перед отправкой скрывайте секреты |
| `sudo dnsctl restart` | Перезапустить только этот DNS |
| `sudo dnsctl stop` / `start` | Остановить / запустить DNS |
| `sudo dnsctl backup` | Полная копия с секретами; краткая остановка DNS |
| `sudo dnsctl resume` | Продолжить незавершённую установку, сохранив настройки |
| `sudo dnsctl renew` | Проверить продление сертификата Cloudflare |
| `sudo dnsctl certificates` | Проверить/скопировать обновлённые PEM и перезапустить DNS |

Cloudflare-сертификат проверяется таймером systemd дважды в сутки. После
реального продления перезапускаются только два контейнера Personal DNS.
Посмотреть таймер: `systemctl status personal-dns-renew.timer`.
При собственных PEM добавьте `dnsctl certificates` в deploy-hook своего
ACME-клиента. Источники должны сохранить те же пути.

Резервные копии лежат в `/opt/personal-dns-backup-*.tar.gz`. Это **секретные
файлы**, включая сертификаты и Cloudflare Token. Храните их зашифрованно и
вне GitHub. Автоматическое восстановление и обновление приложения в этой
первой версии не реализованы. Не заменяйте установку запуском install.sh:
он специально откажется перезаписать уже существующий каталог.

## Безопасность и ограничения

- Идентификатор в DoH/DoT — секретный адрес доступа. Не публикуйте его,
  скриншоты `info`, архив данных или токен Cloudflare.
- Client ID — не полноценная криптографическая аутентификация устройства.
  В DoT имя видно в DNS/SNI наблюдателю сети. Для строгой изоляции используйте
  DNS внутри VPN; эта сборка рассчитана на личное небольшое использование.
- Разрешён только созданный Client ID. Неизвестные DoH-пути получают 404,
  обычный DNS и QUIC не публикуются; админка не доступна через DoH-порт.
- Ставятся лимиты частоты запросов. Это не защита от объёмного DDoS.
- По умолчанию журналы DNS-запросов и статистика выключены. Upstream-запросы
  отправляются Quad9/Cloudflare по HTTPS; это не полностью независимая
  рекурсия и не обещание анонимности перед upstream-провайдерами.
- Если 853 занят, установка останавливается: Android не позволяет задать
  произвольный DoT-порт. Используйте другой сервер или самостоятельно
  разберитесь с существующим сервисом. Установщик его не отключает.
- IPv6-вход, multi-user управление, автоматическая смена Client ID, DoQ,
  публичный обычный DNS, произвольные ОС и авторитетные зоны не входят в v1.
